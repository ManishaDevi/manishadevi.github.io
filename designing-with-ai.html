The question Inventory managers at a hub pharmacy open their home screen to answer one thing: what needs my action today, and what happens if I wait?

How I split the work with AI

  1. Me

    Frame

    Started from what I learned shipping the platform: the four personas, the decisions they make each morning, and the data behind those decisions.

  2. AI

    Generate

    Claude Design produced four layouts for the same screen and the same data, each tagged with a UX principle.

  3. Me

    Evaluate

    Compared the layouts by what actually differed, not by the name or principle each one came with.

  4. Me

    Decide what needs a screen

    Sorted each alert into interface, agent or automation before choosing a layout.

User needs and UX principles shaping AI-generated layouts

UX principles: Hick’s law, Gestalt proximity and Fitts’s law. One order removes the “where do I start?” decision, problem, evidence and fix sit together, and the large button is the obvious next step. All three hold whether the alerts are rows or cards.

As a ranked list

As cards

UX principle: Chunking by time: the same content as the list and the cards, arranged by deadline instead of by rank. It answers “what can wait?” while keeping today’s list short.

Why I went ahead with this concept: Alerts are grouped by deadline, so the time-sensitive ones come first and users see what needs attention straight away. The work is time-sensitive, so this layout fits it best.

UX principle: Master–detail with progressive disclosure: scan the issues on the left, see the evidence and act on the right, without leaving the page.

Step 2 · Added the components each action needs

  • Required inputs. Quantity to request, delivery location, urgency and notes for a purchase; source pharmacy and quantity for a transfer.
  • Button placement. Where the action sits relative to the inputs it submits.
  • Headers. How the medicine name and code introduce each row.
  • Grouping. Which information sits together horizontally, and which stacks vertically.

Why I kept the vertical timeline

  • At a glance it reads as “these are my points for today, and this is the task against each one”.
  • It makes the work easy to discover and easy to scan.
  • Without it, the rows run together and the screen is harder to read at a glance.

Final screen

Shortages, delayed transfers, cycle counts and expiry were mixed in one list, but an inventory manager handles each as a separate job. So I went ahead with summary cards that work as filters.

Visual refinements

1. Fewer strokes, more structure

  • Each row had an outer stroke, and every input inside it had its own, so a single row stacked many borders.
  • I replaced the row stroke with a soft shadow to separate rows, and reduced the stroke width of the inputs.

2. A cleaner focus state

  • Clicking an input drew a thicker outline on top of its existing border, so the field showed two rings.
  • Now the field’s own border turns blue, with no extra outline.

After: the border itself changes

3. Type, spacing and colour

  • Reworked the spacing, and how “Today” and the “Quantity to request” label are set.
  • Adjusted the colour and weight of the placeholder text in Notes.
  • Timeline dots now carry urgency: red for today, yellow for tomorrow.

4. Confirmation where the action happened

  • After Send to Purchaser, the confirmation used to appear at the top of the page, away from the row the user just acted on.
  • Now it appears in that row, saying what was sent and where.
